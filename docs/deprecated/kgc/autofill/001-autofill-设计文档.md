## 一、需求背景

`kgc.autofill` 提供"源结构 → 目标结构"智能转换能力。用户只需传入：
1. 源数据（任意结构，字段名与目标不同）
2. 一条目标结构示例（定义输出字段）

LLM 自主推断映射关系，输出完整的目标结构数据及每个字段的置信度。

与 `kgc.enrich` 的区别：enrich 需要手动定义 tasks（指定源字段和目标字段的对应关系），autofill 完全由 LLM 自主推断。

## 二、核心设计

### 2.1 设计理念

- **极简接口**: 不需要定义 tasks，只需传源数据 + 目标示例
- **自主推断**: LLM 决定源字段到目标字段的映射关系
- **纯输出**: 响应只包含目标结构，不含源字段
- **无可信标注**: LLM 自评置信度不可靠，去掉置信度，`null` 代替无法推断的值

### 2.2 与 kgc.enrich 的对比

| 对比项 | kgc.enrich | kgc.autofill |
|--------|------------|--------------|
| 字段映射 | 手动定义 tasks | LLM 自主推断 |
| 输出结构 | 源结构 + 填充字段 | 纯目标结构 |
| 置信度 | 无 | 无（已移除） |

## 三、API 接口

**方法名**: `kgc.autofill`

**请求**:
```json
{
  "profile_id": "demo",
  "data": [
    {"title":"青花瓷瓶","era":"明代"},
    {"title":"唐三彩马","era":"唐代"}
  ],
  "targets_example": [
    {"product_name":"青花瓷瓶","dynasty":"明代"}
  ]
}
```

**响应**:
```json
{
  "data": [
    {"product_name":"青花瓷瓶","dynasty":"明代"},
    {"product_name":"唐三彩马","dynasty":"唐代"}
  ]
}
```

## 四、Prompt 设计

### 4.1 System 提示词

包含以下要素：
- 角色定义（数据转换助手）
- 目标字段列表（从 targets_example 提取）
- 输出格式（直接值，null 代替无法推断的字段）
- 目标结构示例

### 4.2 User 提示词

```
数据:
行1: {"title":"青花瓷瓶","era":"明代"}
行2: {"title":"唐三彩马","era":"唐代"}
```

## 五、内部处理流程

```
用户请求
  │  data (源结构多行)
  │  targets_example (定义目标结构)
  ▼
服务端校验
  │  data ≤ 100 行
  │  targets_example 非空 + 字段集合一致
  ▼
构建 prompt
  │  System: 目标字段 + 输出格式 + 示例
  │  User: 源数据格式化
  ▼
LLM 输出
  │  [{"product_name":"青花瓷瓶","dynasty":"明代"},...]
  ▼
解析 + 构建目标结构
  │  直接提取 LLM 输出的值
  │  无法推断的为 null
  ▼
返回
  纯目标结构数据
```

## 六、请求/响应校验

### 6.1 请求校验

| 校验项 | 规则 |
|--------|------|
| data | 非空，≤ 100 行 |
| targets_example | 非空，所有示例的字段集合必须一致 |

### 6.2 响应处理

| 场景 | 处理 |
|------|------|
| LLM 返回行数 < 请求行数 | 截断处理，日志告警 |
| LLM 返回行数 > 请求行数 | 截断到请求行数 |
| 目标字段缺失 | 该字段输出 `nil` |
| LLM 返回 `null` | 该字段输出 `nil` |

## 七、已知限制

1. 仅支持纯文本，不支持图片字段
2. 每行独立处理，不做跨行推断
3. 所有 targets_example 示例必须具有一致的字段集合

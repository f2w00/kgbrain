## 1. 实现了什么

将原本扁平的 `internal/` 包结构重构为 DDD 四层架构, 同时清理了大量废弃代码。

### 1.1 新分层

| 层 | 包 | 职责 |
|---|------|------|
| **domain** | `domain/profile/`, `domain/mapping/` | 业务实体 + 接口定义, 零外部依赖 |
| **infra** | `infra/store/`, `infra/repo/`, `infra/llm/` | 技术实现: SQLite、LLM 调用 |
| **delivery** | `delivery/rpc/` | JSON-RPC handler, 只依赖 domain 接口 |
| **app** | `app/run.go` | 依赖组装, 持有所有具体实现引用 |

### 1.2 删除的废弃包

- `internal/profile/` → 迁移到 `domain/profile/` + `infra/repo/`
- `internal/operation/mapping/` → 迁移到 `domain/mapping/` + `infra/repo/` + `infra/llm/`
- `internal/rpc/` → 迁移到 `delivery/rpc/`
- `internal/store/` → 迁移到 `infra/store/`
- `internal/agents/` — 未使用
- `internal/orchestrator/` — 未使用
- `internal/notify/` — 未决议, 清除
- `internal/middleware/` — 未使用

### 1.3 测试迁移

- `tests/unit/operation/mapping/` → `tests/unit/domain/mapping/`

## 3. 关键实现点

### 3.1 接口放置策略

- `ProfileRepository` 放在 `domain/profile/repository.go`
- `CacheRepository` 放在 `domain/mapping/repository.go`
- `LLMClient` 放在 `domain/mapping/service.go` (消费侧定义)
- infra 包不定义重复接口, 隐式实现 domain 接口

### 3.2 工厂模式隔离

`LLMClientFactory` 类型定义在 `domain/mapping/service.go`, 具体工厂函数在 `app/run.go` 中注入:

```go
llmFactory := func(baseURL, apiKey, model string) (mapping.LLMClient, error) {
    return llm.NewClient(baseURL, apiKey, model)
}
```

handler 只依赖 `mapping.LLMClientFactory`, 不导入 `infra/llm`。

### 3.3 CacheRepository 返回领域类型

`CacheRepository.Get` 返回 `*mapping.Mapping` (领域类型), 而不是内部 DTO。 `cacheRow` 结构体小写不导出。

### 3.4 BuildMappingPrompt 返回 string

`domain/mapping/prompt.go` 中的 `BuildMappingPrompt` 返回 `string`, 不导入 `eino/schema`。
`infra/llm/openai.go` 负责将 string 包装为 `schema.Message`。

## 4. 已知限制或待改进点
